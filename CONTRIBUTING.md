## Getting Started

### 1. Clone the repo
```bash
git clone https://github.com/YOUR_USERNAME/DocuMind.git
cd DocuMind
```

### 2. Create and activate a virtual environment
```bash
# Windows
python -m venv .venv
.venv\Scripts\activate

# Mac / Linux
python -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies
```bash
pip install -r requirements.txt
```

### 4. Set up your environment variables
```bash
# Copy the template
cp .env.example .env

# Open .env and fill in your API keys — never commit this file
```

### 5. Checkout your branch
```bash
git checkout feat/YOUR-AREA
```

## Daily Workflow

### Before you start coding each session
Always pull the latest changes from main first to stay up to date:
```bash
git checkout main
git pull origin main
git checkout feat/YOUR-AREA
git merge main
```

### While you work
Commit small and often — do not save everything for one giant commit at the end:
```bash
git add .
git commit -m "feat: description of what you did"
git push origin feat/YOUR-AREA
```

### When your task is ready for review
1. Go to the repo on GitHub
2. Click **Compare & pull request** next to your branch
3. Write a short description of what you built
4. Assign **@ZARD1991** as reviewer
5. Link the relevant GitHub Issue(s) by writing `Closes #ISSUE_NUMBER` in the PR description
6. Move the Issue card to **In Review** on the kanban board

### After your PR is approved
P5 (the integration lead) will merge it into main. Do not merge your own PR.

---

## Commit Message Format

Every commit message must start with one of these prefixes:

| Prefix | When to use |
|--------|-------------|
| `feat:` | New functionality added |
| `fix:` | Bug or error corrected |
| `chore:` | Setup, config, dependencies, cleanup |
| `docs:` | README, comments, this file |
| `test:` | Evaluation scripts, test queries |
| `refactor:` | Code restructured without changing behavior |

### Examples
```
feat: add PDF parser with page number extraction
fix: handle empty chunks in vector store loader
chore: add pymupdf to requirements.txt
docs: update README with HPC run instructions
test: add 10 baseline eval questions to data/eval
```

## Branch Rules

- **Never push directly to `main`** — it is protected and will reject direct pushes
- **Never commit to someone else's branch** without asking them first
- Each person owns one branch — keep your changes inside your own files
- If you need something from another person's module, coordinate with them and use their function via import once it is merged to main

## Never Commit These

The `.gitignore` already covers most of these, but be aware:

| What | Why |
|------|-----|
| `.env` | Contains real API keys — never expose these |
| `chroma_db/` | Large local database, regenerated by running the pipeline |
| `data/raw/` | Scraped files, can be large and regenerated |
| `__pycache__/` | Auto-generated Python cache |
| `.venv/` | Local virtual environment |

If you accidentally commit any of these, tell P5 immediately so it can be removed from history.

## GitHub Issues and Kanban Board

- Every task has a corresponding GitHub Issue
- When you start a task, move its card from **Backlog → In Progress**
- When you open a PR, move it to **In Review**
- When the PR is merged, close the Issue — it moves to **Done** automatically
